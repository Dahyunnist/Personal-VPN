# Windows 全隧道双栈断线保护

## 保护目标

全隧道配置启用后，客户端只允许 VPN 外层 TCP 连接和发往专用 Wintun 接口的流量离开本机。IPv4、IPv6 其他出口均在 Windows Filtering Platform（WFP）阻断。协议 v2 支持 IPv4 与 IPv6 内层数据包；配置 `::/0` 后 IPv6 经隧道传输。

保护持续到用户显式关闭。断开 VPN、网络重连、客户端崩溃或 Windows 重启都不自动移除过滤策略。管理员可以修改或删除策略，因此它不抵御本机管理员或内核级恶意软件。

## 启用约束

- 全隧道需配置 `allow_default_route: true`，IPv4/IPv6 按需分别加入 `0.0.0.0/0`、`::/0`。
- `server.host` 必须是数字 IP。域名解析会在锁定生效前产生 DNS 流量；数字 IP 避免该泄漏，也使重启后仍可连接固定端点。
- `expected_name` 仍独立用于 TLS 证书身份验证，不能改成跳过名称校验。
- Linux 客户端传输没有可用的全隧道 kill switch；会拒绝全隧道连接，不会降级成无保护模式。

## Windows 策略

客户端在连接 VPN 前，以 WFP 持久 provider/sublayer 原子安装策略：

1. 持久策略只允许 VPN 服务器 IP/TCP 端口，并在 IPv4/IPv6 的 outbound packet 和 transport 层阻断其他流量。
2. 安装 outbound IPv4/IPv6 boot-time 阻断过滤器。BFE 启动时，Windows 在 boot-time 和持久策略之间原子切换；boot-time 阶段先封锁所有 IP 出口。
3. 客户端进程存活期间，另用 WFP 动态会话放行当前 Wintun 接口。此例外不写入持久策略；进程崩溃或退出时由 WFP 自动删除。这样接口索引变化或被复用时，重启后不会误放行其他接口。
4. 移除该 Wintun 接口上由本项目创建的陈旧默认路由，再为 VPN 服务器端点安装更精确的主机路由，避免全隧道路由递归到自身。
5. 只有持久封锁和动态隧道例外成功安装后才尝试 VPN 连接。任一步失败均不添加隧道路由；已提交的持久保护保持封锁。

WFP 自定义 provider GUID 用于只枚举和删除本项目创建的过滤器。过滤器更新使用事务；失败时旧策略保持不变。禁用保护前先清除本项目创建的陈旧默认路由；清理失败则不移除封锁策略。

## 手动解除

在桌面客户端确认 VPN 已断开后，点击“关闭全局断线保护”，再确认恢复普通网络。该操作只删除本项目的 WFP provider/sublayer/filters，并清理专用 Wintun 接口上本项目创建的默认路由；不会重置 Windows 防火墙或其他 VPN 规则。精确指向 VPN 服务器的 `/32` 或 `/128` 主机路由可能保留。它只影响到该服务器地址的选路，不放行其他流量；如需清理，应在确认接口、目标地址和路由归属后单独删除，不要批量清理 NETMGMT 路由。

如果 GUI 无法正常打开，可从命令提示符运行 `personal-vpn-client.exe --disable-kill-switch`；程序会请求管理员权限并执行相同的窄范围清理。

过滤器保留时，未运行客户端只允许 VPN 服务器端点通信；客户端运行后还允许当前 Wintun 接口。服务器 IP 变更、配置改为 split tunnel、WFP/BFE 故障或用户无法打开 GUI 时，系统可能持续离线。需要先通过提升权限的 PersonalVPN 客户端解除保护，再更改配置。不要通过清空系统路由表或重置整个防火墙恢复网络。

## 验收边界

编译和单元测试不能证明操作系统实际应用了 WFP 过滤器。首次启用前必须在可回滚的 Windows 客户端虚拟机中验证：连接前/隧道中断/进程强杀/重启期间的 IPv4、IPv6、DNS、TCP、UDP、ICMP 出口；VPN 服务器外层 TCP 的唯一放行；禁用保护后的恢复；以及 Windows 防火墙/安全软件共存。需要客户端和服务端两个逻辑端点，可运行在同一物理主机的两台虚拟机中；WSL 不能替代 Windows WFP 验证。

当前未在宿主机启用该策略，也未完成虚拟机抓包/强杀/重启验收。部署前不得把单元测试结果当作真实防泄漏证明。
