# 历史凭据轮换操作手册

## 适用范围

仓库历史中曾包含服务器和客户端证书、私钥及客户端 PKCS#12 文件。删除这些文件只清理当前树，不会从 Git 历史或已有克隆中撤回它们。曾公开的私钥一律按已泄露处理。

本仓库当前历史扫描发现的凭据路径包括：

- `vpn_base/server/certs/server.crt`、`server.key`；
- `vpn_base/server/client_config/client.crt`、`client.key`；
- `vpn_client&server/client/certs/` 下的客户端/服务器证书、私钥和 `client.p12`；
- `vpn_client&server/server/certs/` 下的服务器证书和私钥；
- `test/certs/` 与 `task1/` 下的测试证书、私钥和 PKCS#12 文件。

凭据清理提交为 `bd16553`。它不代表 Git 历史已重写，也不证明凭据从未部署。当前仓库没有可确认仍有效的生产凭据；部署方必须核实主机、备份、CI 密钥库和客户端配置。

## 处置决策

1. 若这些凭据只用于本地测试，确认没有部署或复用后，重新生成测试 PKI 即可。不要将新生成的密钥写入仓库。
2. 若任何服务器或客户端曾使用这些凭据，立即按泄露事件处理。暂停相关 VPN 接入，记录当前证书指纹、签发者、序列号、部署位置和活跃客户端。
3. Git 历史中未发现 CA 私钥文件，但这不能证明它未在其他位置泄露。历史中暴露过服务器私钥，必须建立全新 CA 信任锚；即使旧 CA 私钥安全，也不能只在旧 CA 下重签叶证书。客户端 schema v1 不检查服务器 CRL；schema v2 才启用该能力。
4. 用新 CA 签发全新的服务器证书/私钥和客户端证书/私钥。服务器仅信任新客户端 CA，客户端仅信任新 CA。若仍有旧部署，发布吊销泄露证书的 CRL；客户端必须使用 schema v2 并配置服务器叶证书 CRL，不能假设 v1 客户端会拒绝已撤销的服务器身份。

## 生产轮换步骤

1. **准备新凭据。** 在受控的 CA/密钥管理环境生成新私钥。每台服务器和每台客户端使用独立叶密钥。CA 私钥不得放进仓库、客户端包或普通服务器目录。
2. **验证候选材料。** 核对证书用途、SAN、有效期、签发链和公钥匹配；记录证书 SHA-256 指纹。私钥权限遵循服务账号 `0600` 或 Windows 客户端 ACL 策略。
3. **建立切换窗口。** 客户端 schema v2 支持服务器叶证书 CRL 检查，但没有经过验证的双 CA 迁移流程。准备好新服务器证书/密钥、服务器 CRL、新 CA、新客户端 CA、新客户端证书/密钥及客户端 v2 配置，再安排协调切换；切换期间可能需要短暂停服。
4. **替换服务端材料。** 原子安装新服务器证书、私钥、新客户端 CA 和 CRL。服务端只信任新客户端 CA。按部署手册重载或重启服务端；不要把旧 CA 留在新客户端信任包中。
5. **替换每台客户端材料。** 安装新 CA、客户端证书、私钥及配置。删除旧密钥和 PKCS#12 备份；从备份恢复前先确认备份不含旧凭据。
6. **验证拒绝与接入。** 使用旧客户端凭据连接必须失败；使用新客户端凭据必须成功。配置服务器 CRL 的 v2 客户端必须拒绝已撤销服务器证书，并只接受新服务器身份。保存脱敏日志、指纹和验证时间。
7. **关闭旧身份。** 确认所有客户端迁移后，停止信任旧 CA、删除旧证书/密钥、轮换可能共用的密码，并审查访问日志。若使用 CRL，确认新 CRL 已加载；现有会话需要重启服务端才能全部终止。
8. **处理 Git 历史。** 凭据撤销/替换优先于历史清理。若需清理公开历史，另建镜像克隆和可恢复离线备份，按 GitHub 敏感数据流程重写准确路径，再协调强制更新和协作者重新克隆。不要在工作克隆上试验历史重写。

## 回滚边界

回滚不能重新启用已泄露的证书、私钥或旧信任锚。新材料验证失败时，回滚到另一套未泄露、仍受信任的凭据；否则保持服务停止并修复切换。不要把旧凭据作为应急回滚副本。

## 验收记录

记录事件编号、UTC 时间、受影响路径/主机/设备、旧和新证书指纹、旧凭据撤销或信任移除证据、CRL 生效结果、旧凭据拒绝测试、新凭据成功测试、备份处置结果及 Git 历史清理决定。不要把私钥、令牌或完整敏感配置放入记录。
