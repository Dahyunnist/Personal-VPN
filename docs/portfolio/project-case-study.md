# Personal-VPN 项目复盘与面试指南

## 一句话定位

这是一个面向物联安全/安全通信场景的跨平台 VPN 技术预研项目：使用 C++17、Boost.Asio、OpenSSL、Linux TUN 和 Windows Wintun，实现 Windows 客户端到 Linux 服务端的双向 IPv4 加密隧道，并在原始原型基础上持续改进协议正确性、安全边界、异步生命周期、资源治理、测试和发布工程。

在导师确认真实业务背景前，应使用“技术预研/原型”表述，不应声称项目已进入产品、上线、服务客户或达到生产规模。

## 可核验的个人技术产出

- 设计 20 字节有界帧协议，解决 TLS/TCP 字节流拆包、粘包和消息顺序问题。
- 将虚拟地址分配权交给服务端，以客户端证书指纹绑定带代次的租约，阻止地址冒用。
- 用 strand、单写队列、缓冲区所有权和背压处理异步并发与生命周期边界。
- 实现多客户端 Linux 服务端、TUN 数据包路由、会话上限、握手/空闲超时和 JSON 指标。
- 实现 Windows mTLS 客户端、严格配置文件校验、私钥 ACL 预检，以及 Wintun 地址/MTU/路由的事务化配置和精确回滚。
- 根据真实运行状态重建 UI，移除全局状态、内嵌私钥、shell 命令拼接、假连接成功和线程 detach。
- 建立跨平台单元/集成/端到端测试、ASan/UBSan、libFuzzer、基准测试、CI、CPack 和发布门禁。

## 从原型到工程实现

| 原型风险 | 改造措施 | 工程价值 |
|---|---|---|
| 把一次 TLS read 当作一个 IP 包 | 明确帧头和增量解码器 | 正确处理 TCP 拆包/粘包，并限制内存 |
| 由客户端声明虚拟 IP | 证书身份加服务端租约 | 绑定认证与网络授权，避免地址冲突/冒用 |
| 多处并发读写同一 TLS stream | strand 加单写队列 | 满足异步流的串行访问约束 |
| 异步操作引用临时内存 | 使用 shared/owned buffer | completion 前数据持续有效 |
| Windows 路由修改没有事务 | 分步记录并反序回滚 | 部分失败和退出不破坏原有网络 |
| 全局对象和 detach 线程 | 单一所有权树、可中断等待和 join | 停止流程确定、可测试、无后台悬挂 |
| 内嵌证书私钥 | 只保存路径，并检查权限/ACL | 降低仓库泄密和本机越权读取风险 |
| 没有资源边界 | 设置载荷/队列/会话/线程/超时上限 | 慢客户端和恶意输入不能无限占用资源 |
| 只能证明“能跑” | 测试、sanitizer、fuzz、CI、打包和文档 | 结果可回归、可审查、可交付 |

## 建议准备的五个 STAR 故事

### 1. TLS 是字节流，不是数据包

- **情境：** 原型假设一次读取对应一个数据包；网络分片或合并后会造成解析错误。
- **任务：** 设计跨平台、可增量解析且有资源上限的隧道协议。
- **行动：** 定义 magic/version/type/flags/length/sequence；实现失败即关闭的增量解码器；覆盖分片、多帧、非法长度、乱序和模糊输入。
- **结果：** 协议边界不再依赖 TLS 读取边界，并形成可测试的 v1 状态机。

### 2. 异步写生命周期与并发

- **情境：** 多方向转发可能并发触发写操作；临时 packet buffer 可能在 completion 前销毁。
- **任务：** 保证同一 TLS stream 同时只有一个写操作，且数据一直有效。
- **行动：** 用 strand 串行化操作；使用拥有缓冲区的队列、字节/帧上限和统一关闭路径。
- **结果：** 并发行为变成确定状态机，可由队列、超时和 sanitizer 测试验证。

### 3. Windows 网络配置回滚

- **情境：** Wintun、地址、MTU 或路由任一步失败，都可能留下不一致网络状态。
- **任务：** 确保失败、断开和异常退出时，只撤销本次创建的对象。
- **行动：** 将网络设置建模为事务，逐步记录已完成操作并精确反序回滚；用可注入后端在每个失败点执行单元测试。
- **结果：** 启停可重复执行，不再依赖可能破坏用户原有路由的广泛删除命令。

### 4. 认证不等于授权

- **情境：** 即使 TLS 证书有效，客户端仍可能伪造虚拟 IP 或发送其他人的源地址。
- **任务：** 建立设备身份到隧道地址的授权关系。
- **行动：** 用证书指纹作为身份，由服务端分配租约；上下行都校验地址；租约携带 generation，避免延迟回调释放后来复用的地址；支持通过 CRL 撤销设备。
- **结果：** 数据面权限不再依赖客户端自报信息。

### 5. 从功能演示到可验证工程

- **情境：** 原始仓库缺少架构、自动化测试、性能边界和发布证据。
- **任务：** 让新的评审者可以复现构建并判断项目质量。
- **行动：** 建立跨平台 CI、Linux 测试、sanitizer、fuzz、CPack、校验和、威胁模型、部署/排障文档和诚实的性能实验方法。
- **结果：** 项目可支撑围绕网络、C++、并发、安全和工程化的系统性技术交流。
