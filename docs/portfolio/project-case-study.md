# Personal-VPN 项目复盘与面试指南

## 一句话定位

这是一个面向物联安全/安全通信场景的跨平台 VPN 技术预研项目：使用 C++17、
Boost.Asio、OpenSSL、Linux TUN 与 Windows Wintun，实现 Windows 客户端到 Linux
服务端的双向 IPv4 加密隧道，并在原始原型基础上完成协议正确性、安全边界、异步
生命周期、资源治理、测试和发布工程化升级。

在导师确认真实业务背景前，应使用“技术预研/原型”表述，不应声称已进入产品、上线、
服务客户或达到生产规模。

## 可核验的个人技术产出

- 设计 20 字节有界帧协议，解决 TLS/TCP 字节流拆包、粘包和消息顺序问题。
- 将虚拟地址分配权移到服务端，以客户端证书指纹绑定带代际的租约，阻止地址冒用。
- 用 strand、单写队列、缓冲区所有权和背压修复异步并发与生命周期边界。
- 实现多客户端 Linux 服务端、TUN 包路由、会话上限、握手/空闲超时与 JSON 指标。
- 实现 Windows mTLS 客户端、严格配置、私钥 ACL 预检，以及 Wintun 地址/MTU/路由
  的事务化配置和精确回滚。
- 用真实运行状态重建 UI，移除全局状态、内嵌私钥、shell 命令拼接、假连接成功和线程
  detach。
- 建立跨平台单元/集成/E2E 测试、ASan/UBSan、libFuzzer、基准、CI、CPack 和发布门禁。

## 从原型到工程化实现

| 原型风险 | 改造 | 可解释的工程价值 |
|---|---|---|
| 一次 TLS read 被当作一个 IP 包 | 明确帧头 + 增量解码器 | 正确处理 TCP 拆包/粘包，限制内存 |
| 客户端声明虚拟 IP | 证书身份 + 服务端租约 | 认证与网络授权绑定，避免地址冲突/冒用 |
| 多处并发读写同一 TLS stream | strand + 单写队列 | 满足异步流的串行访问约束 |
| 异步操作引用临时内存 | shared/owned buffer | completion 前数据始终有效 |
| Windows 路由修改非事务化 | 分步记录 + 逆序回滚 | 部分失败和退出不破坏原有网络 |
| 全局对象和 detach | 单一所有权树 + 可中断等待 + join | 停止过程确定、可测试、无后台悬挂 |
| 内嵌证书私钥 | 仅路径配置 + 权限/ACL 检查 | 降低仓库泄密和本机越权读取风险 |
| 无资源边界 | payload/队列/会话/线程/超时上限 | 慢客户端和恶意输入不会无限占用资源 |
| 只能“能跑”证明 | 测试、sanitizer、fuzz、CI、包和文档 | 结果可回归、可审查、可交付 |

## 建议准备的五个 STAR 故事

### 1. TLS 是流，不是包

- **Situation:** 原型隐含假设一次读取对应一个数据包，网络分片或合并后会错包。
- **Task:** 设计跨平台、可增量解析、资源有上限的隧道协议。
- **Action:** 定义 magic/version/type/flags/length/sequence；实现失败锁定的增量解码器；
  覆盖分片、多帧、非法长度、乱序和模糊输入。
- **Result:** 使协议边界独立于 TLS read 边界，形成可测试的 v1 状态机。

### 2. 异步写生命周期与并发

- **Situation:** 多方向转发会并发触发写，临时 packet buffer 可能在 completion 前销毁。
- **Task:** 保证一个 TLS stream 同时只有一个写操作且数据存活。
- **Action:** 通过 strand 串行化、owned buffer 队列、字节/帧上限和统一 close 路径处理。
- **Result:** 并发行为转化为确定状态机，可由队列、超时和 sanitizer 测试验证。

### 3. Windows 网络配置回滚

- **Situation:** Wintun、地址、MTU、路由任一步失败都可能留下脏网络状态。
- **Task:** 确保失败、断开和异常退出路径只撤销本次创建的对象。
- **Action:** 将网络设置建模为事务，逐步记录已完成动作，逆序精确回滚；用可注入后端
  在每个失败点做单元测试。
- **Result:** 启停变为可重复操作，不会用广泛删除命令破坏用户原有路由。

### 4. 认证不等于授权

- **Situation:** 即使 TLS 证书有效，客户端仍可能伪造虚拟 IP 或发送别人的源地址。
- **Task:** 建立设备身份到隧道地址的授权关系。
- **Action:** 用证书指纹作为身份，由服务端分配租约；上下行都校验地址；租约加入 generation
  防止延迟回调释放后来重用的地址；CRL 支持设备撤销。
- **Result:** 数据平面权限不再依赖客户端自报信息。

### 5. 从功能演示到可证明工程

- **Situation:** 原仓库缺少架构、自动测试、性能边界与发布证据。
- **Task:** 让陌生评审可以复现构建并判断质量。
- **Action:** 建立跨平台 CI、18 项 Linux 测试、sanitizer、fuzz、CPack、校验和、威胁模型、
  部署/排障文档和诚实的性能实验方法。
- **Result:** 项目可以支撑围绕网络、C++、并发、安全和工程化的系统性技术深挖。

4. Linux `ip_forward` 与 NAT 分别解决什么问题？为什么程序不直接执行 iptables？
5. 为什么 TLS over TCP 仍然需要应用层 framing？
6. 帧长度在分配内存前如何验证？decoder 失败后为什么不能继续复用？
7. sequence 防了什么，为什么它不能替代 TLS 的防重放？
8. 为什么同一个 Asio SSL stream 不能随意并发写？strand 的保证是什么？
9. `async_write` 的 buffer 在什么时候可以释放？项目如何保证所有权？
10. 背压在哪里发生，队列满时为什么选择 fail closed？
11. `io_context` 为什么会提前退出，work guard 与 outstanding operation 有何关系？
12. stop、timer 和 I/O completion 同时发生时如何保证幂等？
13. 为什么不 detach 阻塞中的 Wintun 线程？项目如何唤醒并 join？
14. mTLS 完成后为什么还要做租约与源/目的地址校验？
15. 证书指纹身份的优势和局限是什么？证书轮换时会发生什么？
16. CRL、OCSP、短期证书各有什么运维权衡？
17. 租约 generation 解决了哪类 ABA/延迟回调问题？
18. 多客户端下 TUN 收到返回包后如何找到唯一 session？
19. 为什么 registry 调用 peer 前必须释放 mutex？
20. 如何限制恶意客户端的内存、连接、握手和空闲资源消耗？
21. Windows 路由事务如何区分自己创建的条目与原有条目？
22. 私钥文件权限检查能防什么，不能防什么？TOCTOU 如何进一步收紧？
23. 为什么 TLS/TCP 可能出现 TCP-over-TCP meltdown？何时考虑 UDP/QUIC？
24. 如何公平比较直连与 VPN 的吞吐、RTT 和 CPU？
25. codec 微基准为什么不能当作 VPN 吞吐？
26. 如何设计 24 小时稳定性测试并判断内存泄漏？
27. sanitizer、fuzz、单元测试分别覆盖什么，为什么不能互相替代？
28. 如果新增 IPv6，需要改哪些协议、授权、路由和测试边界？
29. 如果要热更新证书/CRL，如何避免影响已有 session？
30. 如果生产化，第一批不会写代码解决的问题是什么？（PKI、主机加固、监控、发布、
    回滚、审计、容量与事故响应。）
